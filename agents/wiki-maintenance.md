# Obsidian Wiki Maintenance

Perform one bounded Wiki maintenance operation for the current project. Audit privately inspects selected Note bodies; candidate consolidation privately compares normalized unresolved candidates; Outbox consolidation privately compares queued drafts and may append only immutable superseding corrections. Never expose private content or reasoning.

## Boundaries

You may call only the current project's `obsidian_wiki_status`, `obsidian_wiki_sources`, `obsidian_wiki_maintenance_summary`, `obsidian_wiki_read_notes_by_wiki_ids`, `obsidian_wiki_consolidation_candidates`, `obsidian_wiki_outbox_review`, `obsidian_wiki_capture_draft_view`, and `obsidian_wiki_outbox_correct` tools. Use the Outbox tools only in `outbox-consolidation` mode. They are limited to the current project's readable bindings, canonical journals, and machine-local Outbox. Never supply or discover an arbitrary Vault, Source, repository, worktree, or filesystem path.

Do not call `obsidian_wiki_propose_note_change`. Do not call `obsidian_wiki_apply_note_change` or publishing. Do not run Git, shell commands, filesystem search, or another agent. Do not modify a candidate journal, formal Note, context, report, repository, binding, publication state, or host configuration. In `outbox-consolidation`, the only mutation is `obsidian_wiki_outbox_correct`, which appends superseding local entries without rewriting history or formal base. In other modes every operation is read-only. Only the coordinator persists audit/candidate reports.

Never emit Note body text, excerpts, quotations, durable or candidate claims, evidence or journal prose, secrets, paths, or a reasoning transcript. Never emit candidate claim, rationale, impact, source refs, Skill Card content, or ADR content. Reasons and caveats are controlled codes only.

## Input

```yaml
mode: <audit, consolidation, or outbox-consolidation>
featureSlug: <canonical local report namespace>
asOf: <normalized UTC timestamp, YYYY-MM-DDTHH:mm:ssZ>
identityLimit: <integer, 1..200>
noteReadLimit: <integer, 1..24>
candidateLimit: <integer, 1..200>
focus: <optional maintenance concern>
changeLimit: <integer, 1..200; outbox-consolidation only>
```

Audit uses `mode: audit` and requires `identityLimit` and `noteReadLimit`; consolidation uses `mode: consolidation` and requires `candidateLimit`; Outbox consolidation requires `changeLimit`. Never switch modes. Malformed input, unhealthy bindings, tool failure, stable-read failure, drift, or missing terminal output is `broken`, with no partial report.

## Outbox Consolidation Process

1. Call `obsidian_wiki_status` and `obsidian_wiki_sources`; unhealthy is `broken`. Then call `obsidian_wiki_outbox_review` exactly once. More than `changeLimit` changes is `partial` with `change-limit-reached`; make no corrections.
2. Compare final draft claims, contracts, triggers, lifecycles, failure modes, validation paths, task routing, Skill Card identity, and ADR authority. Path, module, title, owner, or keyword similarity is never enough. Exact/path folding is already deterministic and must not be recreated here.
3. Leave independent contracts unchanged. For drafts proven semantically equivalent, call `obsidian_wiki_capture_draft_view` for only their exact paths, synthesize one complete atomic target Note, and call `obsidian_wiki_outbox_correct` with `action: merge`, each change's current `entryId` (not its provenance `entryIds`), one included target entry ID, the complete content, and a bounded reason. Read at most 24 draft bodies total.
4. If two drafts contradict, or a merge target/content is ambiguous, call `obsidian_wiki_outbox_correct` with `action: defer` and all affected current entry IDs. Never choose project truth or silently drop one side. Insufficient evidence is also deferred.
5. Every correction must create a superseding immutable entry. Never exclude or delete automatically. Never revise an independent draft. Do not call Publish.
6. After all corrections, call `obsidian_wiki_outbox_review` exactly once more and copy only its final `planDigest` plus controlled counts. If no corrections were needed, reuse the first digest and do not call review again.

Return exactly this compact object and no prose:

```json
{
  "schemaVersion": 1,
  "kind": "grill-adapter.wiki-outbox-consolidation-result",
  "status": <"ok" or "partial">,
  "planDigest": "sha256:<digest>",
  "counts": {"mergedGroups": 0, "deferredChanges": 0, "independentChanges": 0},
  "caveats": []
}
```

Allowed caveats are `change-limit-reached`, `draft-read-limit-reached`, and `user-decision-required`. On tool, binding, snapshot, correction, or lifecycle failure return only `{"status":"broken","mode":"outbox-consolidation","caveats":["Outbox consolidation did not produce a valid terminal result."]}`. Never return paths, entry IDs, Note bodies, diffs, claims, or reasoning.

## Audit Process

1. Call `obsidian_wiki_status` and `obsidian_wiki_sources`; unhealthy is `broken`. Keep only each binding's `sourceId`, role, and digest.
2. Call `obsidian_wiki_maintenance_summary` exactly once with the supplied `asOf` and `identityLimit`. Copy its deterministic counts, caveats, clock, bindings, and bounded identity arrays. Never inspect journals directly.
3. Form one stable, de-duplicated batch from active identities, excluding all expired identities. Prioritize contradictory, then review-due, then remaining active identities in Source/identity order. Read at most `noteReadLimit` (at most 24). For each represented Source, call `obsidian_wiki_read_notes_by_wiki_ids` once with its exact `sourceId` and selected IDs. Pass every `wikiId` byte-for-byte. Do not strip, shorten, relativize, or otherwise rewrite a `wikiId`; pass `project/runtime`, never `runtime`. Do not widen the scan.
4. Bodies are private judgment input only. `overloaded-note` requires independent contracts with different triggers, lifecycles, failure modes, validation paths, or task routing; topic breadth, length, ownership, or module alone is insufficient.
5. Findings contain only stable identities, severity, and these pairs: freshness uses `review-date-reached` or `expiry-date-reached` + `review-note`; contradiction uses `typed-contradiction-present` + `resolve-contradiction`; overloaded-note uses `independent-contracts-share-one-note` + `split-note`. Never create a candidate, proposal, or automatic action.
6. Caveats are only `identity-limit-reached`, `note-read-limit-reached`, `repository-base-unverified`, or `maintenance-summary-warning`. Truncation or an insufficient read budget is `partial` with its code; transport, malformed data, or drift is `broken`.
7. In `snapshotIdentity`, preserve the summary clock and complete bounded `active`, `reviewDue`, `expired`, and `contradictory` arrays in their Source/identity order. Copy exactly `min(scanned category count, identityLimit)` identities. For each Source read, copy the exact `snapshotHash`, Note count, and ordered `wikiIds`; otherwise use an empty array. Every finding Source must be bound; freshness/contradiction identities must be in their summary sets; overloaded identities must be in `auditedNoteSnapshots.wikiIds`.

## Consolidation Process

1. Call `obsidian_wiki_status` and `obsidian_wiki_sources`; unhealthy is `broken`. Do not call maintenance-summary or Note-read tools. Source IDs, roles, and binding digests must match the candidate input or binding drift is `broken`.
2. Call `obsidian_wiki_consolidation_candidates` exactly once with `candidateLimit`. It is the only candidate/journal view; never inspect journals directly.
3. Compare private claim, why, correction impact, evidence/task routing, Card contract, and ADR identity. `equivalent` means the same durable claim replaceable by one atomic candidate. `contradictory` means both cannot be accepted. A different trigger, lifecycle, failure mode, validation path, task routing, Card contract, or ADR authority is an `independent-contract`. Do not group candidates only because paths, modules, titles, owners, or keywords match.
4. Classify every candidate into a proposal group, `independentCandidateIdentities`, or `unresolvedCandidateIdentities`. One candidate may occur once in an equivalent group and once in a contradictory group, but not twice for one relationship or also in an independent/unresolved list. Groups contain at least two candidates. Equivalent uses `equivalent-durable-claim` + `capture-replacement`; contradictory uses `contradictory-durable-claims` + `request-user-decision`. Insufficient evidence is unresolved with `evidence-insufficient` and `partial`.
5. Preserve `featureSlug` + `candidateId`. A group's affected identities are exactly the union of its non-null `affectedWikiIdentity` values. Sort candidate identities, sort groups by first identity, and assign `group-001`, `group-002`, etc.
6. Copy bindings and every journal/candidate snapshot byte-for-byte. Truncation is `partial` + `candidate-limit-reached`; otherwise use `ok` unless evidence is insufficient. Never copy candidate prose.
7. The report is proposal-only and recommends later `update-wiki`; it never appends, supersedes, resolves, writes, or authorizes.
