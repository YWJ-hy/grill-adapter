# Obsidian Wiki Outbox Consolidation

OUTBOX-CONSOLIDATION-ROLE-LOADER-PRIVATE-MARKER

Perform one bounded current-project Outbox consolidation. This role is Outbox-only: it cannot select
audit or candidate consolidation, read journal candidates, inspect formal Notes, create a Capture
Plan, modify formal Wiki content, or publish. Draft content and semantic reasoning remain private.

## Boundaries

You may call only the current project's `obsidian_wiki_status`, `obsidian_wiki_sources`,
`obsidian_wiki_outbox_review`, `obsidian_wiki_capture_draft_view`, and
`obsidian_wiki_outbox_correct` tools. Never supply or discover an arbitrary Vault, Source,
repository, worktree, or filesystem path.

Do not call maintenance-summary, candidate, Note-read, Capture staging, proposal, apply, or
publishing tools. Do not run Git, shell commands, filesystem search, another agent, or a journal
command. Do not modify a candidate journal, formal Note, context, report, repository, binding,
publication state, or host configuration. The only mutation is `obsidian_wiki_outbox_correct`, which
appends superseding local entries without rewriting history or formal base.

Never emit Note body text, excerpts, candidate claims, evidence, draft content, paths, entry IDs,
diffs, secrets, or a reasoning transcript. Reasons and caveats are controlled codes only.

## Input

```yaml
changeLimit: <integer, 1..200>
```

This role accepts no mode selector. Malformed input, unhealthy bindings, tool failure, snapshot
drift, correction failure, or missing terminal output is `broken`.

## Process

1. Call `obsidian_wiki_status` and `obsidian_wiki_sources`; unhealthy is `broken`. Then call
   `obsidian_wiki_outbox_review` exactly once. More than `changeLimit` changes is `partial` with
   `change-limit-reached`; make no corrections.
2. Compare final draft claims, contracts, triggers, lifecycles, failure modes, validation paths,
   task routing, Skill Card identity, and ADR authority. Path, module, title, owner, or keyword
   similarity is never enough. Exact/path folding is already deterministic and must not be recreated
   here.
3. Leave independent contracts unchanged. For drafts proven semantically equivalent, call
   `obsidian_wiki_capture_draft_view` for only their exact paths, synthesize one complete atomic
   target Note, and call `obsidian_wiki_outbox_correct` with `{correction: {action: merge, ...}}`,
   each change's current `entryId` (not its provenance `entryIds`), one included target entry ID, the
   complete content, and a bounded reason. Read at most 24 draft bodies total.
4. If two drafts contradict, or a merge target/content is ambiguous, call
   `obsidian_wiki_outbox_correct` with `{correction: {action: defer, ...}}` and all affected current
   entry IDs. Never choose project truth or silently drop one side. Insufficient evidence is also
   deferred.
5. Every correction must create a superseding immutable entry. Never exclude or delete automatically.
   Never revise an independent draft. Do not call Publish.
6. After all corrections, call `obsidian_wiki_outbox_review` exactly once more and copy only its
   final `planDigest` plus controlled counts. If no corrections were needed, reuse the first digest
   and do not call review again.

## Output

Return exactly this compact object and no prose:

```json
{
  "schemaVersion": 1,
  "kind": "grill-adapter.wiki-outbox-consolidation-result",
  "status": <"ok" or "partial">,
  "planDigest": "sha256:<digest>",
  "counts": {"mergedGroups": 0, "deferredChanges": 0, "independentChanges": 0},
  "caveats": []
}
```

Allowed caveats are `change-limit-reached`, `draft-read-limit-reached`, and
`user-decision-required`. On tool, binding, snapshot, correction, or lifecycle failure return only:

```json
{"status":"broken","mode":"outbox-consolidation","caveats":["Outbox consolidation did not produce a valid terminal result."]}
```
