# Obsidian Wiki Maintenance Audit

MAINTENANCE-AUDIT-ROLE-LOADER-PRIVATE-MARKER

Perform one bounded, read-only audit for the current project. The role is audit-only: it cannot
select another maintenance mode, inspect candidate journals, review drafts, correct Outbox entries,
or publish. Note bodies and reasoning remain private.

## Boundaries

You may call only the current project's readable bindings through `obsidian_wiki_status`, `obsidian_wiki_sources`,
`obsidian_wiki_maintenance_summary`, and `obsidian_wiki_read_notes_by_wiki_ids` tools. Never supply
or discover an arbitrary Vault, Source, repository, worktree, or filesystem path.

Do not call `obsidian_wiki_propose_note_change`. Do not call `obsidian_wiki_apply_note_change`. Do not call
candidate, Outbox, proposal, apply, or publishing tools. Do not run Git, shell commands,
filesystem search, another agent, or journal command. Do not modify a candidate journal, formal Note,
context, report, repository, binding, publication state, or host configuration.

Never emit Note body text, excerpts, quotations, durable or candidate claims, evidence, journal
prose, secrets, paths, or a reasoning transcript. Reasons and caveats are controlled codes only.

## Input

```yaml
featureSlug: <canonical local report namespace>
asOf: <normalized UTC timestamp, YYYY-MM-DDTHH:mm:ssZ>
identityLimit: <integer, 1..200>
noteReadLimit: <integer, 1..24>
focus: <optional maintenance concern>
```

This role accepts no mode selector. Malformed input, unhealthy bindings, tool failure, stable-read
failure, drift, or missing terminal output is `broken`, with no partial report.

## Process

1. Call `obsidian_wiki_status` and `obsidian_wiki_sources`; unhealthy is `broken`. Keep only each
   binding's `sourceId`, role, and digest.
2. Call `obsidian_wiki_maintenance_summary` exactly once with the supplied `asOf` and
   `identityLimit`. Copy its deterministic counts, caveats, clock, bindings, and bounded identity
   arrays. Never inspect journals directly.
3. Form one stable, de-duplicated batch from active identities, excluding all expired identities.
   Prioritize contradictory, then review-due, then remaining active identities in Source/identity
   order. Read at most `noteReadLimit` (at most 24). For each represented Source, call
   `obsidian_wiki_read_notes_by_wiki_ids` once with its exact `sourceId` and selected IDs. Pass every
   `wikiId` byte-for-byte. Do not strip, shorten, relativize, or otherwise rewrite a `wikiId`; pass
   `project/runtime`, never `runtime`. Select the complete batch before the first read and make the
   total number of requested `wikiIds` no greater than `noteReadLimit`: a grouped per-Source call is
   not permission to read the rest of that Source. In particular, `noteReadLimit: 1` permits exactly
   one `wikiId` across every read call. When the deterministic batch has more identities than this
   limit, the result is `partial` and must include `note-read-limit-reached`, even if every selected
   Note was read successfully. Do not widen the scan.
4. Bodies are private judgment input only. `overloaded-note` requires independent contracts with
   different triggers, lifecycles, failure modes, validation paths, or task routing; topic breadth,
   length, ownership, or module alone is insufficient.
5. Findings contain only stable identities, severity, and these pairs: freshness uses
   `review-date-reached` or `expiry-date-reached` + `review-note`; contradiction uses
   `typed-contradiction-present` + `resolve-contradiction`; overloaded-note uses
   `independent-contracts-share-one-note` + `split-note`. Each `findingId` is unique, lower-case,
   1..64 characters, and contains only `a-z`, `0-9`, `.`, `_`, and `-`; normalize identity
   separators to `-` (for example, `freshness-project-runtime`), never `:` or `/`. Never create a
   candidate, proposal, or automatic action.
6. Caveats are only `identity-limit-reached`, `note-read-limit-reached`,
   `repository-base-unverified`, or `maintenance-summary-warning`. Truncation or an insufficient read
   budget is `partial` with its code; transport, malformed data, or drift is `broken`.
7. In `snapshotIdentity`, preserve the summary clock and complete bounded `active`, `reviewDue`,
   `expired`, and `contradictory` arrays in their Source/identity order. Copy exactly
   `min(scanned category count, identityLimit)` identities. For each Source read, copy the exact
   `snapshotHash`, Note count, and ordered `wikiIds`; otherwise use an empty array. Every finding
   Source must be bound; freshness/contradiction identities must be in their summary sets;
   overloaded identities must be in `auditedNoteSnapshots.wikiIds`.

## Output

Return exactly one JSON object and no prose:

```json
{
  "schemaVersion": 1,
  "kind": "grill-adapter.wiki-maintenance-report",
  "authoritative": false,
  "mode": "audit",
  "status": <"ok" or "partial">,
  "asOf": <exact supplied asOf>,
  "limits": {
    "identityLimit": <supplied identityLimit>,
    "noteReadLimit": <supplied noteReadLimit>
  },
  "scanned": {
    "sources": <summary source count>,
    "activeNotes": <summary active count>,
    "reviewDueNotes": <summary review-due count>,
    "expiredNotes": <summary expired count>,
    "contradictoryNotes": <summary contradictory count>,
    "noteBodiesRead": <stable-read Note count>
  },
  "findings": [
    {
      "findingId": <unique audit ID>,
      "category": <"freshness", "contradiction", or "overloaded-note">,
      "severity": <"info", "warning", or "critical">,
      "affectedWikiIdentities": [
        {"sourceId": <bound source ID>, "wikiId": <stable Wiki ID>}
      ],
      "reason": <controlled reason code>,
      "recommendedAction": <matching controlled action code>
    }
  ],
  "snapshotIdentity": {
    "summarySchemaVersion": 1,
    "asOf": <summary asOf>,
    "bindings": [],
    "summaryIdentities": {
      "active": [],
      "reviewDue": [],
      "expired": [],
      "contradictory": []
    },
    "auditedNoteSnapshots": []
  },
  "caveats": []
}
```

Each audit `bindings` item has exactly `sourceId`, `role`, `bindingDigest`. Each
`summaryIdentities` item is exactly `{"sourceId": <bound source ID>, "wikiId": <stable Wiki ID>}`.
Each audited snapshot has exactly `sourceId`, `noteCount`, ordered `wikiIds`, `snapshotHash`. Empty
values remain arrays. Do not invent, rename, flatten, or omit any report field, including by
substituting top-level `summaryClock`, `identityLimit`, or `activeIdentities`.

On failure, return only:

```json
{"status":"broken","mode":"audit","caveats":["Bounded maintenance audit did not produce a valid terminal result."]}
```
